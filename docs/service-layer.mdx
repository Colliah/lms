# Service Layer Documentation

The service layer contains all business logic and database operations, separated from the API layer for better testability and maintainability.

## Architecture Principles

### 1. Separation of Concerns
- **Services**: Handle business logic, database queries, complex calculations
- **Actions**: Handle authentication, input validation, error transformation

### 2. Error Handling
- Services **throw errors** for any failure
- Actions **catch** and transform errors into user-friendly responses
- UI displays error messages from action responses

### 3. Type Safety
- All functions use TypeScript with strict typing
- RORO pattern (Receive an Object, Return an Object)
- Import enums from generated Prisma client

```typescript
export async function getDailyVocabulary(
  params: GetDailyVocabularyParams
): Promise<DailyVocabularyResult>
```

**Logic**:
1. Fetch words due for review (`nextReviewDate <= now`)
2. Calculate remaining slots for new words
3. Fetch new words matching user's proficiency level
4. Include related data (audio, images, examples)
5. Limit total to `maxWords` (default: 20)

**Usage**:

### submitReview

Processes a vocabulary review using the SM-2 spaced repetition algorithm.

```typescript
interface SubmitReviewParams {
  userId: string;
  wordId: string;
  quality: ReviewQuality; // AGAIN, HARD, GOOD, EASY
}

interface SubmitReviewResult {
  nextReviewDate: Date;
  intervalDays: number;
  mastered: boolean;
}

export async function submitReview(
  params: SubmitReviewParams
): Promise<SubmitReviewResult>
```

**SM-2 Algorithm Implementation**:

```typescript
function calculateSM2(params: SM2Params): SM2Result {
  const qualityMap = {
    AGAIN: 0,
    HARD: 3,
    GOOD: 4,
    EASY: 5,
  };
  
  const q = qualityMap[quality];
  
  // Calculate new ease factor
  let newEaseFactor = easeFactor + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02));
  newEaseFactor = Math.max(1.3, newEaseFactor); // Minimum 1.3
  
  // Calculate interval
  if (q >= 3) {
    // Successful review
    if (repetitionCount === 0) newIntervalDays = 1;
    else if (repetitionCount === 1) newIntervalDays = 6;
    else newIntervalDays = Math.round(intervalDays * newEaseFactor);
    newRepetitionCount += 1;
  } else {
    // Failed review - reset
    newIntervalDays = 1;
    newRepetitionCount = 0;
  }
  
  return {
    easeFactor: newEaseFactor,
    intervalDays: newIntervalDays,
    repetitionCount: newRepetitionCount,
    nextReviewDate: new Date(Date.now() + newIntervalDays * 86400000),
  };
}
```

**Process**:
1. Get or create UserWordProgress
2. Apply SM-2 algorithm based on quality rating
3. Update progress record
4. Log review in UserWordReview
5. Update DailyActivity counters
6. Mark as mastered if appropriate criteria met

## Service Layer Best Practices

### 1. Always Use Transactions for Complex Operations
```typescript
await prisma.$transaction(async (tx) => {
  await tx.userWordProgress.update(...);
  await tx.userWordReview.create(...);
  await tx.dailyActivity.upsert(...);
});
```

### 2. Validate Input Before Database Operations
```typescript
if (!userId || !wordId) {
  throw new Error("Missing required parameters");
}
```

### 3. Use Descriptive Error Messages
```typescript
throw new Error("Failed to fetch vocabulary: user not found");
```

### 4. Return Structured Data
```typescript
return {
  success: true,
  data: { ... },
  meta: { ... }
};
```

### 5. Log Errors for Debugging
```typescript
catch (error) {
  console.error("serviceFunctionName error:", error);
  throw new Error("User-friendly error message");
}
```
