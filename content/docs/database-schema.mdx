# Database Schema Documentation

This document provides a comprehensive overview of the Learning Management System database schema implemented with Prisma ORM.

## Overview

The LMS uses PostgreSQL with Prisma ORM and includes 35+ models organized into the following domains:

- **Authentication & User Management**
- **Vocabulary System with SM-2 Spaced Repetition**
- **Grammar Exercises**
- **Reading Comprehension**
- **Writing Practice**
- **Speaking & Pronunciation**
- **Progress Tracking & Gamification**
- **Analytics**

## Core Models

### Authentication Models

These models are managed by Better Auth and extended for the LMS.

#### User

```prisma
model User {
  id                  String    @id
  name                String
  email               String    @unique
  emailVerified       Boolean   @default(false)
  image               String?
  createdAt           DateTime  @default(now())
  updatedAt           DateTime  @updatedAt
  
  // Relations to LMS features
  profile             UserProfile?
  preferences         UserPreferences?
  wordProgress        UserWordProgress[]
  wordReviews         UserWordReview[]
  // ... more relations
}
```

**Purpose**: Central user model for authentication and authorization.

#### Session, Account, Verification

Standard Better Auth models for session management, OAuth accounts, and email/phone verification.

## Vocabulary System

### Word

```prisma
model Word {
  id          String         @id @default(cuid())
  word        String         @unique
  translation String
  phonetic    String?
  definition  String
  partOfSpeech PartOfSpeech
  difficulty  ProficiencyLevel
  
  categories  WordCategory[]
  audios      WordAudio[]
  images      WordImage[]
  examples    ExampleSentence[]
  userProgress UserWordProgress[]
}
```

**Purpose**: Stores vocabulary words with translations and metadata.

**Key Fields**:
- `partOfSpeech`: Enum (NOUN, VERB, ADJECTIVE, etc.)
- `difficulty`: Proficiency level (A1, A2, B1, B2, C1, C2)

### UserWordProgress

```prisma
model UserWordProgress {
  id              String   @id @default(cuid())
  userId          String
  wordId          String
  
  // SM-2 Algorithm Fields
  easeFactor      Float    @default(2.5)
  intervalDays    Int      @default(1)
  repetitionCount Int      @default(0)
  nextReviewDate  DateTime @default(now())
  mastered        Boolean  @default(false)
  
  user            User     @relation(...)
  word            Word     @relation(...)
  reviews         UserWordReview[]
  
  @@unique([userId, wordId])
}
```

**Purpose**: Tracks individual user progress for each word using the SM-2 spaced repetition algorithm.

**SM-2 Fields Explained**:
- `easeFactor`: Difficulty multiplier (min 1.3, default 2.5)
- `intervalDays`: Days until next review
- `repetitionCount`: Consecutive successful reviews
- `nextReviewDate`: Calculated review date
- `mastered`: True when word is considered learned

### UserWordReview

```prisma
model UserWordReview {
  id         String        @id @default(cuid())
  userId     String
  wordId     String
  progressId String
  quality    ReviewQuality
  reviewedAt DateTime      @default(now())
  
  user       User                 @relation(...)
  word       Word                 @relation(...)
  progress   UserWordProgress     @relation(...)
}
```

**Purpose**: Logs individual review sessions for analytics.

**ReviewQuality Enum**: `AGAIN`, `HARD`, `GOOD`, `EASY`

## Grammar System

### GrammarTopic

```prisma
model GrammarTopic {
  id          String           @id @default(cuid())
  name        String           @unique
  description String?
  difficulty  ProficiencyLevel
  exercises   GrammarExercise[]
}
```

**Purpose**: Categories for grammar exercises (e.g., "Present Simple", "Past Perfect").

### GrammarExercise

```prisma
model GrammarExercise {
  id          String       @id @default(cuid())
  topicId     String

  description String?
  difficulty  ProficiencyLevel
  
  topic       GrammarTopic @relation(...)

  userProgress UserGrammarProgress[]

```

### GrammarQuestion

```prisma
model GrammarQuestion {
  id            String       @id @default(cuid())
  exerciseId    String
  type          ExerciseType
  question      String
  options       String[]     // JSON array for multiple choice

  orderIndex    Int
```

**ExerciseType Enum**: `MULTIPLE_CHOICE`, `FILL_IN_BLANK`, `REORDER`, `MATCHING`

```prisma

  id             String   @id @default(cuid())
  userId         String
```

## Database Relationships

### Key Patterns

1. **User-Centric Design**: All learning data is tied to the `User` model
2. **Progress Tracking**: Separate progress models for each learning module
3. **Many-to-Many**: Words ↔ Categories, Achievements ↔ Users
4. **One-to-Many**: Exercises → Questions, Passages → Questions
5. **One-to-One**: UserWriting → WritingFeedback

## Indexes and Performance

Key indexes for optimal query performance:

```prisma
// Frequently queried fields
@@index([userId, nextReviewDate])  // UserWordProgress
@@index([userId, date])            // DailyActivity
@@index([difficulty])              // Words, Passages, Exercises
@@unique([userId, wordId])         // UserWordProgress
```

## Migration Strategy

To apply this schema:

```bash
# Generate Prisma Client
bun run db:generate

# Push to database (development)
bun run db:push

# Or create migration (production)
bunx prisma migrate dev --name init_lms_schema
```
